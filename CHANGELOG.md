# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- The tags an adapter wraps evidence in no longer change with every request. A tag name is now a family that the instructions name, the same for the whole process, and a keyed digest of the block, so the instructions and every page are sent byte for byte the same from one request to the next and a provider can serve them from its prompt cache. On the seed dataset with the OpenAI adapter, two repeats, 100,345 of 144,838 input tokens were read from the cache, against none before. A forged tag is now told from a real one by its family, and after a leak of the family only by its code, which is weaker than a name drawn per request; a probe with forged tags and what it does not show are in [docs/prompts.md](docs/prompts.md).

### Added

- The seed dataset gains a case whose answer is on two pages that follow each other: the fault code on one page of the sprayer manual and the check that names the cause on the next, which does not repeat the code. It is the first case in which `neighbours` brings a needed page into a small limit: ranked by wording the second page comes sixth of eight, with one neighbouring page on each side it is sent within a limit of four. Not yet run against a model.
- `machine_fault_triage.adapters.claude.ClaudePhotoReader`: photos of a fault report read by a Claude model, one call per photo, like `OpenAIPhotoReader`. Checked against a stand-in for the API only.
- `eval judge REPORT --dataset DIR --judge MODULE:CALLABLE --out FILE` and `judge_run`: a judging model's opinion on whether the verified quotes and cited records of each cause support it, added to a finished report as `quote_supports_cause` with the verdict and reason per cause. No triage is run again. The report names the judge and the fingerprint of its instructions, a comparison says when two runs were judged differently, and a cause the judge could not answer for is left unjudged with the reason, while a judge that answers for none fails the command. `--context` shows the judge each quote with its paragraph, `--workers N` makes several calls at once, and the summary counts the verdicts, the first causes supported and the causes left out for lack of verified evidence ([ADR 0002](docs/adr/0002-score-evaluations-in-code.md)).
- Evaluation runs read photos: a case names the photos of its report as files inside the dataset, `run_eval(..., photo_reader=...)` and `eval run --photo-reader MODULE:CALLABLE` read them before pages are selected, and `expect.photo_shows` scores the reading on its own as `photo_read`. A report records the reader and the tokens it spent, and a comparison says when two runs read photos differently. The seed dataset gains three cases whose code is only on a drawn display.
- `TriageResult.report_facts`: what the customer reported, restated by the model as one plain fact per line, without greetings, feelings or contact details, so that a technician need not read the report. `unreported_figures` lists every code or number in it that the report and its photos do not hold. Prompt version 4 asks for it and is the new default; evaluation cases take `expect.report_keeps` and `expect.report_omits`, scored by `report_restated`, and the seed dataset gains three noisy reports.
- `machine_fault_triage.render.render_text`: a result laid out as plain text for a technician, safety first, each cause with numbered checks, the fix and its sources. Unverified quotes, pages recognised from a scan, corrected page numbers and unsupported numbers are always printed. `Labels` replaces the English headings.
- A quote the model placed on the wrong page is no longer lost: a quote of five words or more that stands on another page of the same document is verified there, `DocumentCitation.page` names that page and `cited_page` the one the model gave. The new `cited_page_right` metric reports how often the model's page was right ([ADR 0001](docs/adr/0001-verify-citations-outside-the-model.md)).
- `Page.small_images` counts the icon-sized pictures embedded on a PDF page, and a sync notes the pages that hold five or more, because what such pictures show is missing from the text. Stored manuals are read again once for this.
- Character recognition for scanned manuals: `load_pdf(..., ocr=...)`, `FolderLibrary(..., ocr=...)` and `library sync --ocr MODULE:CALLABLE` recognise the pages that have no text layer; pages with one are left as they are. `OcrEngine` is the port, `machine_fault_triage.adapters.rapidocr.RapidOcrEngine` (the `ocr` extra) runs on the machine and reads two-column pages column by column, and `machine_fault_triage.testing.FakeOcrEngine` is the scripted stand-in. `Page.source` and `DocumentCitation.source` say when text was recognised, a sync notes how many pages were, and a manual is read again when the engine changes. Words hyphenated at a line end are joined on recognised pages too.
- Photos in a fault report: `FaultReport.photos` takes several `Photo` values, and `run_triage(..., photo_reader=...)` has them read before pages are selected, so a code that is only on a photo of the display can find its page. What was read reaches the model as untrusted evidence, and `TriageResult.photo_readings` and `photo_usage` return it with its cost. `photo_limit` and `photo_size_limit` bound the photos, and a report with photos and no reader is refused. `PhotoReader` is the port, `machine_fault_triage.adapters.openai.OpenAIPhotoReader` reads each photo in a call of its own, and `machine_fault_triage.testing.FakePhotoReader` is the scripted stand-in.
- `run_triage(..., device_model=...)`: the model and variant of the device reach the model as evidence, so that an answer can keep to the values a page gives for that model. Evaluation cases take `device_model` and `expect.other_models`, scored by the new `right_model` metric, and the seed dataset gains two data sheets and eight paired cases that differ only in the model, half of them on a table with the models in the header.
- An answer that breaks the schema or is cut off is asked for again, once by default (`run_triage(..., retries=N)`, `eval run --retries N`). The reason goes to the model as untrusted data next to one fixed sentence of instructions. `TriageResult.attempts` counts the model calls, `usage` totals them, and an evaluation summary says how many runs asked again. A refusal is final.
- Bounds on what goes in and comes out of the model. A fault report must not be blank, a document cannot hold two pages with the same number, and `run_triage` refuses evidence in which two documents or two service records share an id. `report_limit` refuses a fault report longer than 20,000 characters unless the caller raises it (`eval run --report-limit N`). `evidence_limit` refuses a request too large for the model before it is paid for; an evaluation run checks every case up front. The answer schema caps every text and list, so a runaway answer is rejected.
- `Generation.detail` and `TriageResult.failure`: a run that failed because the answer broke the schema names the fields that broke it, without the values, field names or types the model made up.
- Token usage on every result: `TriageResult.usage` holds the tokens of the model call, also for a refused or truncated one, and `TriageResult.embedding_tokens` those that page selection spent. `Usage.cached_input_tokens` separates input read from the provider's prompt cache. Embedders and page selectors return the tokens they spent with their values (`Embeddings`, `Selection`). Evaluation reports total and price them with `--cached-price` and `--embedding-price`.

- Evaluation harness: a TOML case format, metrics computed in code, repeated runs with a per-metric summary, and a paired comparison of two runs.
- `machine-fault-triage eval run` and `eval compare` commands.
- `Usage` on `Generation`: adapters report the tokens of each call, and an evaluation report totals them, times every run and prices them with `--price`.
- A seed dataset with two fictional devices and twenty-six cases, including prompt-injection attempts and reports that describe two problems at once.
- `every_problem_answered` and `uncovered_left_open` metrics: a case can list several problems, each needing a cause of its own, and name a reported problem that the evidence does not cover and that must be left open instead of guessed.
- Fault codes are matched however they are typed: `A11`, `a11` and `A-11` find a page that prints `A.11`.
- `machine_fault_triage.adapters.claude.ClaudeModel`, installed with the `anthropic` extra.
- `machine_fault_triage.adapters.openai.OpenAIModel`, installed with the `openai` extra.
- Versioned prompt ([docs/prompts.md](docs/prompts.md)): every version of the instructions is kept, immutable, with a fingerprint pinned by a test. `run_triage(..., prompt_version=N)` and `eval run --prompt N` run an older version. Evaluation reports record the version and fingerprint, and a comparison says when two runs used different prompts or sent different pages. Version 3 defines the confidence levels and says when to abstain.
- `machine_fault_triage.pdf.load_pdf`, installed with the `pdf` extra: reads the text layer of a PDF into a `Document` and rejoins words broken across lines.
- `PageSelector` port and `KeywordPageSelector`: `run_triage(..., pages=...)` and `eval run --pages N` send only the pages that best match the report, and verify quotes against those pages only.
- `Embedder` port, `HybridPageSelector`, `CachedEmbedder` and `machine_fault_triage.adapters.openai.OpenAIEmbedder`: pages are also matched by meaning, so a report in other words or another language than the manual can find its page. Page vectors are kept in a local SQLite file; fault reports are never stored. `eval run` takes `--embedder`, `--embedder-option`, `--embedding-cache` and `--neighbours`, and the report records how pages were selected.
- `Document.supersedes`: an older edition is left out when its replacement is supplied too, so an outdated value cannot be quoted and verified.
- `machine_fault_triage.folder.FolderLibrary` and `machine-fault-triage library sync`: PDF manuals kept as `TENANT/DEVICE/NAME.pdf` are read into a local registry. A sync reads only new and changed files, drops removed ones, reports files it could not read and why, notes what may limit the answers from a file (pages without text, very long pages, a thin text layer), and can delete the stored vectors of pages that no manual holds any more.
- Retrieval metrics in evaluation reports, computed from the order in which a selector ranked the pages it kept: `retrieval_recall`, `retrieval_precision`, `reciprocal_rank` and `retrieval_ndcg`. Selectors expose that order through `rank`.
- `TextSplitter` port and `machine_fault_triage.adapters.chonkie.ChonkieSplitter`, installed with the `chunking` extra: pages can be ranked by their pieces, recursive or fixed with overlap, while whole pages are still sent and cited. `eval run` takes `--chunk-size` and `--chunk-overlap`. Off by default.
- `machine_fault_triage.testing.FakeEmbedder`, a scripted embedder for tests.
- Stricter citation verification: a quote must be at least three words long and match whole words, so a fragment cut out of a longer number no longer verifies.
- `TriageResult.unsupported_figures`: numbers in the answer that occur nowhere in what the model was shown. `TriageResult.prompt_version` records the prompt behind each answer.
- `expected_page_sent` metric: tells a page that page selection never sent apart from a page the model ignored.
- `run_triage`: a baseline run that puts all supplied evidence into one model call and verifies the answer.
- Citation verification: document quotes are checked against the cited page, history citations against the supplied records. Unsupported causes are reduced to low confidence.
- Ports for plugging in a model, a document source and service history: `StructuredModel`, `DocumentProvider`, `HistoryProvider`.
- Untrusted text is passed to the model separately from instructions.
- `machine_fault_triage.testing.FakeModel`, a scripted model for tests and offline examples.
- Result models: status, evidence level, causes with document and history citations, error code, parts, safety warnings and questions for the customer.
